# Выпуск PR 386

## Подтверждено локально

Единая таблица user_records хранит дневник с фотографиями, чек-лист, ручную статистику, общий счёт и регионы России. Для каждого Telegram ID и раздела хранится один текущий снимок, ревизия и последний ID запроса. Сервер проверяет подпись Telegram и возраст авторизации до часа. Ограничения составляют 8 МиБ на запрос, 60 запросов в минуту на аккаунт и раздел, интервал записи не менее секунды. Повтор принятого запроса возвращает ту же ревизию.

Первый импорт требует подтверждения пользователя. Старые локальные ключи сохраняются. Черновики привязаны к аккаунту и разделу. При конфликте черновик предлагается скачать и архивируется локально перед загрузкой сервера. Намеренное удаление записывается пустым массивом или объектом. Пока интерфейс не показал подтверждение сервера, запись может оставаться только на устройстве. При переполнении localStorage нельзя закрывать окно до сохранения или ручного копирования данных.

Страны используют существующий механизм ревизий. Достопримечательности и воды уже имеют отдельные серверные таблицы, поэтому второе хранилище для них не создаётся. Их старые Mini Apps имеют локальные отметки и прежние способы отправки, полная синхронизация этих экранов данным PR не обещается. Кеш курсов валют и настройки конвертера остаются локальными как вспомогательные настройки.

## Порядок переключения

Согласовать окно и управление двумя публикациями до Merge. GitHub Pages автоматически публикует webapp/ при push main. Сначала выпустить бэкенд, убедиться в успешном init_db и остановке старых реплик, затем обеспечить публикацию Pages той же версии. Если Pages обновится раньше, новые персональные экраны блокируют редактирование до доступности API и корректной авторизации. Старые URL и локальные данные остаются, но для входа требуется актуальная inline-кнопка «Открыть» из меню бота.

В init_db добавлены CREATE TABLE IF NOT EXISTS для country_list_revisions, processed_yookassa_payments и user_records. Миграции не очищают данные. Старую версию с новым пользовательским интерфейсом нельзя считать поддерживаемой парой.

На время остановки старого платёжного обработчика обеспечить завершение принятых запросов и временный ответ 503 на входящие webhook при необходимости. Новый обработчик подтверждает платежи через API ЮKassa и фиксирует ID без платных начислений. Проверить реальные настройки секрета и доступ к API в авторизованном сеансе владельца.

После согласованного выпуска один разрешённый аккаунт должен проверить импорт, повторное открытие на другом устройстве, удаление тестовой записи и конфликт двух окон. До отдельного разрешения эти живые проверки не запускать. При 401 после часа сессии заново открыть раздел через бот. При 409 скачать конфликтующий черновик, открыть серверные данные и перенести нужные изменения вручную.

Остановить выпуск при ошибке авторизации корректного аккаунта, доступе к чужим данным, ложном подтверждении записи, ошибках схемы, недоступности API или расхождении версий. Production-доступ, бэкап, регион и права в этой работе не подтверждены.

## Откат

Сохранить новые таблицы и пользовательские данные. При ошибке нового API временно заблокировать запись и оставить локальные черновики. Исправление бэкенда вперёд сохраняет доступ к уже импортированным данным. Откат на старый интерфейс localStorage делает серверные записи недоступными на экране, хотя они остаются в PostgreSQL. Поэтому такой откат требует экспорта или совместимой версии чтения и не является бесшовным.

Не восстанавливать всю БД из предрелизной копии поверх новых пользовательских записей. При необходимости восстановления использовать отдельную базу и сверку. Старый небезопасный webhook нельзя снова выставлять публично.
